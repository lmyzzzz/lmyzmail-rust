# Skibidi banner contract

The SMTP greeting banner is generated by the frozen Skibidi 1.8.0 C library
under `native/lmyzmail-skibidi/upstream`. Rust chooses a 64-bit seed from OS
entropy, but seed expansion, RNG advancement, probability thresholds, output
materialization, variant generation, and batch generation are executed only by
the C library. There is no Rust copy of those algorithms and no Java/JVM
runtime dependency.

## Frozen source

`build.rs` refuses to compile when either frozen input differs:

- `skibidi_avx.c`: `7E8E7F3EE5BEA0AC8D0857BD5BC8D806B44E5142C17EC8B5B6583DB7C62FC613`
- `skibidi_avx.h`: `BDE8E9D19D6668C644ABA1CDD81FB9F56C2236FF827DDD16FB366369BC68BBEA`

The build does not patch those files. It compiles the same translation unit
three times as baseline x86-64 scalar, AVX2, and AVX-512 variants. Command-line
macros rename all 19 public `skibidi_*` exports in each object. This prevents
symbol collisions and gives each variant an independent copy of the C global
configuration. Inherited Rust target features are disabled for these objects,
cc-rs default flags and LTO are disabled, and non-empty C compiler flag
environment variables are rejected so they cannot override the fixed
per-variant ISA.

All three objects use one canonicalized clang executable with an exact
`18.1.3` version token and clang-family check. The build selects
`LMYZMAIL_SKIBIDI_CC`, then the already supported `LMYZMAIL_BPF_CLANG`, then
`clang` from `PATH`; each value is treated as one executable path, never as
a shell command or compiler-plus-arguments string. The explicit compiler path
prevents target `CC` variables or compiler wrappers from being inherited.
Before compilation, the effective cc-rs command is checked for the exact
x86-64 target, baseline `-march`, per-variant `-mavx*` set, and
`-fno-lto`. Unexpected architecture, target-feature, or LTO arguments abort
the build.

After all three archives compile, `build.rs` atomically publishes
`$OUT_DIR/lmyzmail-skibidi-build-manifest.json`. It records the canonical
compiler path, family, exact version, full version line, target, archive names,
and every effective compiler argument for each variant. The manifest is build
evidence; it contains no timestamp or random identifier.

## Mode and dispatch

`JAVA` remains accepted only as a legacy configuration alias. It selects the
frozen scalar C object; it does not select Java, a JVM, a Rust approximation,
or an outer fast path. `SCALAR`, `AUTO`, `AUTO_SAFE`, `NATIVE`, `AVX2`,
`AVX512`, and `AVX-512` retain their existing selection semantics.
Unsupported explicit SIMD modes fail startup.

Rust OS-aware feature detection runs before every entry into an AVX object,
including configuration, version, capability, allocation, and information
queries. AVX2 requires OS-enabled AVX2 state. The AVX-512 object requires
OS-enabled AVX2 plus AVX-512F, AVX-512VL, AVX-512BW, and AVX-512DQ. The scalar
object is compiled for baseline x86-64 with AVX and AVX-512 disabled, so a
low-instruction-set CPU never executes an AVX object merely to discover its
capabilities.

## FFI safety and concurrency

The Rust boundary is narrow and keeps these invariants:

- Contexts are allocated by one variant's `skibidi_alloc_context` and owned by
  an RAII guard that always invokes the same variant's
  `skibidi_free_context`. The C destructor zeroes state before freeing it.
- Each variant has a Rust mutex. The mutex covers C `skibidi_configure`,
  configuration verification, context allocation/initialization, the complete
  generation operation, and context destruction. Concurrent services with
  conflicting global C settings therefore cannot observe one another's
  configuration. A poisoned mutex is recovered without a panic.
- The C ABI layout is checked at runtime: RNG state 128 bytes, context 192
  bytes, and context alignment 64 bytes. The C version must be
  `1.8.0-skibidi-ultra`, and the C-reported active backend must match the
  gated object.
- Single generation uses a 64-byte Rust-owned buffer. Returned lengths must be
  18 through 43 and the bytes must match the bounded ASCII grammar.
- Batch count is capped at 4096. Capacity and offsets use checked arithmetic,
  every returned length and newline is validated, and a short C production
  count fails closed instead of publishing a partial batch.
- Native status codes are mapped to Rust errors. No C pointer or returned
  length is dereferenced before its null, range, ownership, and capacity
  invariants have been checked.

The frozen C API/probability tests, scalar and SIMD same-seed goldens, ABI
probe, ASan/UBSan runs, low-ISA dispatch checks, and concurrent conflicting
configuration test are required release gates for this boundary. A real
release build plus low-ISA/QEMU execution and object disassembly have not yet
run for this change and remain pending; static build-script checks alone are
not evidence that the SIGILL gate has passed.
